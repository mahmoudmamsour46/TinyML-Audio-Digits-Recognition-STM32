ABSTRACT  
Nowadays, microcontrollers are very common in a wide range of applications. Integrating Machine Learning 
with Embedded Systems is essential and should be provided at a low cost to satisfy modern-day requirements. 
The tools that currently exist for this purpose can be used only with the hardware provided by the same vendor, 
and are usually not flexible with IDEs. This paper proposes an open-source framework that helps to deploy a 
trained Neural Network (Both Convolution and Deep Neural Network) on any ARM Cortex M-based microcon-
troller, providing an easy and low-cost device. It converts the trained model with float32 parameters into int8 
type parameters and automatically generates inference code using SIMD optimized CMSIS functions. The output 
obtained using the proposed framework is validated with the X-Cube-AI framework. Also, A voice-based digit 
classification system is implemented using a Cortex-M4 microcontroller to demonstrate the efficiency of this 
procedure.   
1. Introduction 
TinyML focuses on implementing sophisticated deep learning models 
embedded in the same microcontroller, which has the logic to manage 
the connected sensors and actuators. Typically, Machine Learning (ML) 
models are deployed in one of the platforms described in Fig. 1. GPUs 
and FPGAs have high computation power, and are often used in the 
Cloud or edge platforms to perform inference [1]. However, this in turn 
could cause a high latency and make the system dependent on network 
connection. Unlike leveraging the cloud technology, inference done at 
the microcontroller offers significant advantage when implemented in 
industrial scenario and has gained traction in recent years. Since this 
approach does not depend on external resources, latency, network de-
pendency, security and privacy challenges can be avoided, thus facili-
tating an efficient, cost-effective strategy [1]. Also, in many resource 
limited applications like industrial machinery fault diagnosis [2], 
human activity tracking [3], wildlife monitoring [4], and aerial robotics 
[5], microcontrollers are widely adopted. This creates a necessity to find 
a way to deploy ML models on a microcontroller. 
Over the last few years, applications such as spoken keyword spot-
ting [6] and Human Activity Recognition [3] have been implemented in 
real-time on 32-bit low-power microcontrollers. After the network has 
been trained, it is deployed onto a microcontroller to perform the 
inference on the target platform. According to [13], deployment of an 
ML model involves the following phases:  
• Extraction of weights and biases of a given model and encoding to 
desired precision suitable for on-device inference,  
• Development of inference program according to the given model 
graph, 
• Compilation and flashing of the inference program onto the micro-
controller’s flash memory. 
The main challenges faced when deploying ML in microcontrollers 
are limited hardware resources in terms of memory and computation 
speed and lack of a unified TinyML framework for embedded devices [7, 
8]. Most models have floating-point parameters which requires huge 
memory and computation time. This issue is addressed by converting 
float32 into int8 models using post-training quantization techniques [9, 
10], and [11]. [12], deployed a Binary Neural Network (BNN) archi-
tecture for sound event detection in a RISC-V core GAP8 microcontrol-
ler. It is reported that BNN offers 10x better computation efficiency 
when compared to the performance of ARM Cortex-M7 int16 imple-
mentation at the cost of 7.3% lower accuracy. Unfortunately, the

2. Proposed framework for deployment 
Our proposed framework focuses on the most commonly utilized 
Neural Network algorithms. Fig. 2 details the steps involved in deploy-
ing a Neural Network onto a microcontroller. 
The framework is implemented with the help of open-source libraries 
available in Python and can be easily used by everyone. The first step in 
training a CNN model requires obtaining quality data since it forms the 
backbone of any ML model. The algorithm’s performance depends on 
the quality of the data fed to it during the learning phase. Therefore, 
most of the effort is focused on data extraction, cleaning, and analysis. 
Once the data quality is ensured, model development can be carried out 
followed by an evaluation of its accuracy. It should be noted that the 
model is trained with float32 parameters at this stage. 
The different stages in deploying the trained CNN model on a mi-
crocontroller are listed below:  
1. Input a CNN model built using any TensorFlow frame work and parse 
all model parameters (for example, number of layers, weights and 
biases of each layer, number of filters, etc.).  
2. Obtain the scaling parameters using model calibration (Algorithms 1 
and 2), quantize weights, biases to int8 precision and generate library 
files for each layer.  
3. Generate C code for inference engine using CMSIS-NN APIs.  
4. Include the weights and bias library files along with the C code for 
inference in the custom application project of any IDE  
5. Build, deploy and test the application in the microcontroller. 
The proposed framework takes a pre-trained model as input, auto-
mating the process of quantizing the weights, biases, and generation of 
inference code, making it easier to deploy onto the microcontroller. To

3. Convolution neural network for digit classification 
This section explains the bottlenecks in implementing a CNN model 
on an end device and methods for effective real-time execution for a 
voice-based digit classification CNN model. In addition, the steps 
involved in training a CNN model using recorded speech data for the 
classification of digits (0–9) are also discussed briefly. 
3.1. Problem definition 
Efficiency and precision are crucial factors that must be considered 
when implementing CNN models on end devices. Hence, converting the 
parameters from floating-point to fixed-point is necessary to deploy CNN 
models on end devices. This conversion process for obtaining fixed-point 
parameters from the trained CNN model is known as post-training 
quantization [17,18]. Generally, CNNs are highly capable of capturing 
high-level information from images and are used in classification and 
recognition. Its performance in visual processing has been quite prom-
ising that eventually led to achieving convincing results in audio 
recognition. 
Speech-based Digit classification has been utilized to demonstrate 
the working of post-training quantization. The scope of voice-based 
command recognition is increasing rapidly due to the value it adds to 
commercial products. Implementation of CNN is chosen instead of DNN 
due to its superior spectral representations with time-frequency corre-
lations [19]. For voice-based applications, on-device deployment of 
CNN inference is crucial for low power and mobile features. With the 
development of high processing hardware and the availability of public 
datasets, it becomes easier to train and implement a CNN in real-time. 
Google’s Speech Command dataset is aimed at developing on-device 
CNN models that can be used to classify voice-based digit commands

3.2. Feature extraction 
This section explains the Fast Fourier Transform (FFT) method-based 
feature extraction from short digital records using spectrograms. 
Though the Mel-scale spectrogram outperforms the linear scaled one, we 
have chosen the latter for simplicity at the cost of performance [21]. The 
audio signal is sampled at 8000 Hz as per the Nyquist-Shannon sampling 
theorem. The digital waveform acquired for one second is split into 39 
frames of 30 milliseconds, with an overlap of 5 milliseconds as shown in 
Fig. 3. Since the sampling rate is 8000 Hz, each frame would contain 240 
samples and 40 overlap samples. Each frame is transformed into its 
spectrogram representation. To compute the spectrogram, FFT is applied 
to each frame and this results in 256 entries of complex-valued output as

3.3. CNN model architecture and training 
The CNN architecture for the classification of digits based on speech 
input is shown in Fig. 5. As mentioned before, this model has been 
trained to classify the incoming audio recording into one of the 12 
classes. Considering the primary focus is on model quantization, we 
have chosen our network architecture to be relatively simple, with only 
three convolutional layers and one fully-connected layer. In a typical 
CNN architecture, the convolutional layers are used along with ReLU 
based activation functions. Further, the max-pooling layers are used to 
reduce the feature dimensionality. Max pooling is also used to capture 
the time-translation invariance in the input spectrogram image ( [22]). 
The flattened features are given as input to the fully connected layer, 
followed by the SoftMax layer. As shown in Fig. 5, the output SoftMax 
layer reflects the probabilities associated with each pre-defined class. 
Adam optimization algorithm is selected to optimize the training of 
CNN, and cross-entropy is chosen as the loss function [23]. 
Using the TensorFlow framework, the model is trained for 25 epochs, 
with 220 iterations per epoch in a Python environment. Drop-out layers 
are used between each layer to avoid the model memorizing the specific 
features.

4. Post-training quantization 
This section proposes a scheme to deploy the CNN inference engine 
in computationally efficient int8 precision. The quantization scheme is 
detailed for converting a float32 CNN model into an int8 or q7 precision 
fixed point model. 
4.1. Fixed point representation 
An introduction to fixed-point representation is necessary to under-
stand its advantages over floating-point representation. The floating- 
point numbers are generally stored with one bit corresponding to the 
sign, and the remaining bits represent the mantissa and exponent parts. 
It is important to note that there is no fixed number of bits for the integer 
or the exponent parts. According to the IEEE 754 standard, some bits are 
also allocated for special values, like denoting infinity, zero, error, or 
representing a denormalized number. For fixed-point representation, as 
the name suggests, the number of bits allocated for integer and frac-
tional parts is constant, and a separate bit is allocated for the sign. 
In Q [m, n]-format, depending on where the binary point is assumed 
to be, a given number can be interpreted in different ranges [24]. In 
Q-format, m decides signed integer range and n decides the range of the 
fraction to be represented. For example, in q7 or Q [1, 7] precision, 7 bits 
are used for fraction and 1 bit is used for the sign and the supported 
range of float values is (  1,1  2  7).

is necessary to calibrate the weights and activations of the model. This 
dataset can be a small subset (around ~100–500 samples) of the training 
or validation data. Algorithm 1 presents the steps for offline calibration

5. Real time implementation 
This section describes the steps involved in hardware implementa-
tion in detail such as data acquisition from the microphone, spectrogram 
computation, and CNN inference with parameters in q7 format using an

5.1. Hardware 
Using simple and low-cost components, the speech digit classifica-
tion system is implemented at around 25$. For speech acquisition, a low-

with STM32F407 cortex M4 microcontroller, which has 1Mbytes of flash 
memory and 192Kbytes of RAM and has a maximum clock frequency of 
168 MHz. SIMD optimized ARM-CMSIS NN library is used for CNN 
inference implementation. 
The microphone needs a 3 V DC voltage supply and has an internal 
DC bias of VCC/2 (1.5 V). So, the microphone will output a steady 1.5 V 
when the test environment is quiet. The sensor gives an output that is in 
both positive and negative range. Due to the internal bias, the positive

representing 2 s of the signal since the sampling frequency of the ADC 
peripheral is approximately 8000 Hz. The DMA interrupts are config-
ured so that when the first half of the buffer, with 0–7999 samples are 
filled, it triggers the half-complete interrupt and the full complete 
interrupt is triggered when the second half with 8000–15,999 samples 
are filled. The first half of the buffer is referred to as ‘In0’ and the second 
half is named ‘In1’. Once the ADC fills ‘In0’, a half-complete interrupt 
initiates the processing of the first half, and the ‘In1’ gets filled creating a 
cycle of events as shown in Fig. 7. 
The data acquired using the DMA is then used to compute the 
spectrogram. CMSIS-DSP library is used to calculate FFT to generate the 
spectrogram. Fig. 8 shows the sound signal acquired for digit ‘FIVE’ and 
its log scaled spectrogram. 
5.3. CMSIS-NN based implementation 
After the framework computes the q7 format equivalent for the pa-
rameters of the CNN by using the algorithms mentioned, they are loaded 
into the microcontroller’s memory. Open-sourced CMSIS-NN library 
functions are used for convolutions, ReLU, max-pooling, and fully con-
nected layers. During real-time implementation, the spectrogram acts as 
the input for the first layer and needs to be converted into q7 format for 
faster computations. For each layer, among other input parameters, 
finding the re-quantization factor for convolution functions is crucial to 
obtain the inference.

6. Framework evaluation 
This section compares the performance of the models deployed using 
the proposed framework with already existing and established frame-
works like TensorFlow lite for microcontrollers and X-Cube-AI by 
STMicroelectronics. TensorFlow lite is a generalised framework and X- 
Cube-AI is targeted for STM32 based microcontrollers alone. Among 
these two softwares, it was proved by [28], that the performance of 
X-Cube-AI is better than TensorFlow lite for microcontrollers in terms of 
both memory and computation time. So, we have compared our 
framework’s performance with the more efficient X-Cube-AI platform. 
Apart from the voice digit recognition model, the framework is tested 
with other tiny models including Optical Character Recognition (OCR) 
for 0–9 numbers and A-Z alphabets, time-series prediction of the sine 
wave and keyword spotter (similar architecture to [28],). As the pro-
posed framework aims to provide a solution for deploying models in a 
memory efficient way, the comparison is provided by keeping the size 
requirement as the metric. From the results obtained as seen in Table 3, 
the flash and RAM memory used by the proposed framework is lesser 
than the requirement by X-Cube-AI. 
Apart from the memory reduction offered by the framework, another 
advantage of using a quantized model is saving energy consumed by the 
device. For standalone embedded systems, it is important that the device 
consumes lesser energy. This can be achieved by disabling the Floating- 
Point Unit (FPU) during the inference process. Another method to save 
significant amount of energy is by reducing the clock frequency. Using a 
quantized model provides reduction in computation time, which in turn 
would allow us to use a lesser clock frequency. A comparison was done 
to observe how the current consumption varies with core clock along 
with the inference time taken (in milliseconds) for different models as 
seen in Table 4. Based on the data obtained, we can reduce the clock 
frequency from maximum of 168 MHz to 60 MHz, halving the energy 
requirement and still complete the inference in a short period. The 
current consumption data was obtained from the production datasheet 
[29]. 
7. Conclusion 
The framework proposed is used to deploy a trained CNN model in a 
Cortex-M4 microcontroller, automating the quantization and inference 
code generation stages. This work enables a more accessible option for 
researchers and developers to deploy their Neural Networks in the mi-
crocontroller for various applications at low cost. The framework is 
evaluated with several models and the code generated using the pro-
posed method is compared with existing tools like X-Cube-AI. The re-
sults show that the proposed method consumes lesser memory compared 
with X-Cube-AI and also maintains its accuracy similar with the floating- 
point model. In addition, the proposed scheme has been implemented in 
less than 25$ which promises the reality of various on-device AI appli-
cations. The framework can be found in the GitHub repository (link for 
framework).,
